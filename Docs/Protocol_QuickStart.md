# SonarMotorDriver — краткая инструкция по протоколу

Шпаргалка на одну страницу. Полное описание со всеми тонкостями —
[Protocol.md](Protocol.md).

## Подключение

- UART **115200 8N1**, без управления потоком, уровни 3.3 В (нужен USB-UART).
- **USART1**: PA9 = TX платы, PA10 = RX платы (разъём J2: пин 4 — TX, пин 3 — RX, GND общий).
- Дублирующий отладочный порт **USART3** (PB10/PB11) — тот же протокол, можно не подключать.

## Правила обмена

- Протокол текстовый, построчный. Плата принимает `\n`, `\r`, `\r\n`; отвечает всегда `\r\n`.
- На каждую команду — **ровно одна строка ответа**: `ok:...` или `err:...`.
  Дождитесь её перед отправкой следующей (таймаут 400 мс).
- Команды только **строчными** буквами. Максимум 63 символа в строке.
- **Нет ответа вообще** — почти всегда некорректный числовой аргумент (`t=abc`, `v=`),
  а не сбой связи. `err:unknown` — не распознана вся команда.
- Плата шлёт строки и без запроса: телеметрия, `boot:...` при старте,
  `enc:ok`/`err:enc`, `err:stall`. Слушайте порт постоянно.
- Углы кольцевые, `[0,360)`: `t=370` → `10.00`, ход всегда кратчайшим путём (≤180°).

## Команды

| Команда | Действие | Ответ |
| --- | --- | --- |
| `en` / `dis` | Включить / выключить драйвер (цель = текущая позиция) | `ok:en` / `ok:dis` |
| `stop` | Остановить любое движение, драйвер оставить включённым | `ok:stop` |
| `t=180` | Ехать в позицию, ° | `ok:t=180.00` |
| `t=+` / `t=-` | Непрерывное вращение CW / CCW (включает драйвер сам) | `ok:t=+` |
| `scan=0,180,10,100` | Зигзаг: начало, конец, шаг °, пауза мс (до `stop`) | `ok:scan=...` / `err:scan` |
| `scan=0,+,1.5,200` | Бесконечный скан вперёд (`-` — назад) | `ok:scan=...` |
| `sync=0/1/2` | Переход к следующей точке: таймер / фронт SYNC_IN / что раньше | `ok:sync=1` |
| `sync` | Состояние синхронизации | `sync=1 in=0 out=1 n=42` |
| `hold=0` / `hold=1` | Снять / вернуть удержание вала (тихая пауза на замер; цель и точка скана сохраняются) | `ok:hold=0` |
| `hold` | Запрос удержания (без аргумента — состояние, а не установка) | `hold=0` |
| `v=600` | Предел скорости, °/с (1…1200) | `ok:v=600.0` |
| `a=2000` | Предел ускорения, °/с² (0…100000; `0` = без рампы) | `ok:a=2000.0` |
| `kp=` / `ki=` / `kd=` | Коэффициенты PID (старт: 0.025 / 0 / 0) | `ok:kp=0.0250` |
| `op=50` | Период телеметрии, мс (`0` — выключить периодическую) | `ok:op=50` |
| `om=0/1/2` | Источник выдачи: таймер / приход в позицию / оба | `ok:om=1` |
| `om` | Запрос режима выдачи (без аргумента — состояние, а не установка) | `om=1` |
| `debug=0/1` | Краткая / полная телеметрия | `ok:debug=1` |
| `irun 600` / `ihold 300` | Ток движения / удержания, мА (0…3000) | `ok:irun=600` |
| `icur 600 300` | Оба тока сразу | `ok:icur=600,300` |
| `mstep 256` | Микрошаг (1…256, степень двойки; только на стоящем моторе) | `ok:mstep=256` |
| `mcfg` | Конфигурация драйвера | `mode=STEP_DIR run=600 ...` |
| `diag` | Диагностика энкодера на стоящем валу | `ok:diag`, через ~16 мс `enc:ok ...` |

**Запросы состояния** — `sync`, `om`, `hold`, `mcfg` (ключевое слово без `=`).
Отвечают одной строкой **без префикса `ok:`**: это состояние платы, а не
подтверждение команды. Команды установки (`om=1`, `hold=0`, `sync=2`) отвечают
как раньше — `ok:om=1` и т.д. Спрашивайте сразу после подключения: плата могла
перезагрузиться или работать с другим хостом, а `hold` — ещё и вопрос
безопасности (обесточенный вал с виду не отличается от стоящего под током).
Именно так делает [SonarDebugGUI](../Software/SonarDebugGUI/): при подключении
шлёт `mcfg`, `sync`, `om`, `hold`.

Ошибки драйвера: `err:not ready`, `err:bad arg ...`, `err:apply failed`,
`err:busy stop motor first`.

`mstep` проверяется дважды: парсер принимает целое `0…65535` (вне этого
диапазона — **молчание**, значение не приводится к `uint16_t`), а набор
`1/2/4/…/256` проверяет прошивка — на неподходящее отвечает
`err:bad arg (1/2/4/8/16/32/64/128/256)`.

## Телеметрия

```
debug=0:  cp:179.82,ec:0
debug=1:  cp:179.82,tp:180.00,pe:0.18,u:0.0563,m:cl,ec:0,kp:0.0250,ki:0.0000,kd:0.0000,v:600.0,a:2000.0,of:0,drp:0
```

`cp` — позиция, `tp` — цель, `pe` — ошибка по кратчайшему пути, `u` — выход PID,
`m` — `cl`/`ol`, `ec` — код ошибки, `of` — отфильтрованные выбросы энкодера,
`drp` — потерянные строки телеметрии.

**Режим выдачи `om`:** `0` — по таймеру `op` (по умолчанию 4 мс);
`1` — только по приходу в заданную позицию; `2` — оба. Кадр по приходу помечен
последним полем **`ev:1`** (`cp:90.02,ec:0,ev:1`), его `cp`/`tp` — снимок момента
достижения. Один кадр на одну цель (`t=`, `scan=`, каждая точка скана, `en`, `stop`);
при `dis` и `t=±` событий нет. Полная тишина в канале — `om=0` **и** `op=0`.

Разбирайте строки по парам `key:value` через запятую, не по номеру поля.

**Коды `ec`:** `0` — норма, `1` CRC BiSS, `2` энкодер не отвечает, `3` ошибка датчика,
`4` warning, `5` ошибка SPI, `6` выброс отфильтрован, `7` заклинивание вала
(драйвер выключен, держится до `en`). Ошибка энкодера дольше 500 мс → open-loop (`m:ol`).

## Типовые сценарии

**Позиционирование:**

```
en → v=600 → a=2000 → t=90 → ... → stop
```

**Скан с внешним замером (аппаратный хендшейк):**

```
sync=1                  # переход к следующей точке — по фронту SYNC_IN
scan=0,180,5,100        # плата встала на точку → SYNC_OUT=HIGH
                        # сонар делает замер → импульс ≥1 мс на SYNC_IN → едем дальше
stop
```

**Скан с тихим замером (драйвер не шумит во время измерения):**

```
om=1 → scan=0,180,1,5000    # пауза заведомо длиннее замера
< cp:0.01,ec:0,ev:1         # вал на точке
hold=0                      # обмотки обесточены — тишина
                            # ... замер ...
hold=1                      # ток вернулся, вал сел в ту же точку
```

На время `hold=0` скан заморожен (таймер `delay` не тикает, точка не
меняется), цель и уже выданный кадр `ev:1` сохраняются — в отличие от
`dis`/`en`, после которых цель привязывается к текущей позиции.

**Скан без проводной синхронизации (событийная телеметрия):**

```
debug=0 → om=1 → scan=0,180,5,100
< cp:0.01,ec:0,ev:1     # одна строка на точку, канал между точками пуст
< cp:5.00,ec:0,ev:1
...
stop → om=0
```

**Пины синхронизации:** SYNC_OUT (PB9) — выход: LOW = едем, HIGH = точка достигнута.
SYNC_IN (PB12) — вход с pull-down: фронт LOW→HIGH, импульс ≥ 1 мс.

## Грабли

1. Задавайте `t=` **после** `en` — уставка, поданная при `dis`, отбрасывается.
2. Тишина в ответ на команду = проверьте формат числа, а не кабель.
3. При `debug=1` период не опускается ниже 20 мс, как бы мал ни был `op`.
4. `mstep` — только на остановленном моторе (`stop` перед ним).
5. После `err:stall` привод выключен: вернуть в работу может только `en`.
6. `hold=0` — для тихой паузы на замер, `dis` — нет: `en` после `dis`
   сбрасывает цель на текущую позицию, а `hold=1` возвращает к прежней.
