# biss_encoder_stm32cube — драйвер BiSS-C для STM32Cube HAL

Самодостаточная библиотека для чтения абсолютных энкодеров **LENZ IRS** (BiSS-C) по SPI через RS-485 (THVD1452).

> **Статус в этом репозитории:** прошивками из `Software/` эта библиотека
> **не используется** — основная прошивка читает энкодер собственным модулем
> [`FW_SonarMotorDriver/src/biss_c.c`](../../FW_SonarMotorDriver/src/biss_c.c)
> (SPI + DMA напрямую, без слоя портов). Библиотека лежит здесь как
> самостоятельный переносимый драйвер. **Решение о её судьбе принимает человек,
> развилка описана ниже** — см. [«Что с этим делать»](#что-с-этим-делать).
>
> Ядро — `biss_encoder.c`, `biss_protocol.c`, `biss_models.c`, заголовки
> `biss_types.h`, `biss_protocol.h`, `biss_models.h`, `biss_encoder.h` и контракт
> порта `biss_port.h` — **побайтно совпадает** с
> [biss_encoder_arduino](../biss_encoder_arduino/). Различаются только порт
> (`biss_port_stm32_hal.h` + `biss_port_stm32_hal.c` против
> `biss_port_arduino.h` + `biss_port_arduino.cpp`), `library.json`, README
> и каталог `examples/`.

| Возможность | Поддержка |
|-------------|-----------|
| Блокирующее чтение | Да |
| Async (DMA) | Да |

## Подключение (PlatformIO)

```ini
lib_deps =
    file://path/to/Software/lib/biss_encoder_stm32cube
```

## Быстрый старт

```c
#include "biss_encoder/biss_encoder.h"
#include "biss_encoder/biss_models.h"
#include "biss_encoder/biss_port_stm32_hal.h"

static biss_hal_ctx_t   g_hal;
static biss_encoder_t   g_enc;

void HAL_SPI_MspInit(SPI_HandleTypeDef *hspi) {
    biss_port_stm32_hal_spi_msp_init(hspi, &g_hal);
}

g_hal.de_port = GPIOB; g_hal.de_pin = GPIO_PIN_0;
g_hal.re_port = GPIOB; g_hal.re_pin = GPIO_PIN_1;
g_hal.use_dma = 1;

biss_port_t port;
biss_port_stm32_hal_fill(&port, &g_hal);

biss_encoder_cfg_t cfg = { .port = port, .frame = &BISS_LENZ_IRS_17BIT };
biss_encoder_init(&g_enc, &cfg);
```

Полный пример: [`examples/stm32cube_basic`](examples/stm32cube_basic).

```bash
cd examples/stm32cube_basic
pio run
```

## Что с этим делать

Библиотека и её Arduino-близнец сейчас — мёртвый код репозитория: ни одна
прошивка их не собирает (`grep` по `platformio.ini` всех четырёх проектов даёт
ноль упоминаний `biss_encoder_*`). Это осознанное состояние, а не забытый
каталог, но выбор между тремя вариантами остаётся за человеком — ни один из них
не является «очевидно правильным», и сделать его без владельца проекта нельзя.

### Вариант 1. Свести с `src/biss_c.c` основной прошивки

Прошивка начинает читать энкодер через `biss_encoder_*`, свой модуль удаляется.

* **Что придётся сделать.** `src/biss_c.c` (316 строк) и `include/biss_c.h`
  (73 строки) заменяются вызовами библиотеки; DMA-колбэки
  (`DMA1_Channel2/3_IRQHandler`, `HAL_SPI_TxRxCpltCallback`) переезжают в порт;
  `BiSS_Status`/`BiSS_Reading` в `main.c` меняются на `biss_status_t` /
  `biss_reading_t`, а вместе с ними — коды `ec` в телеметрии (сейчас 1–5 приходят
  прямо из `BiSS_Status`), то есть протокол, Python-модель, её тесты и
  конформанс-тест.
* **Что это даёт.** Одна реализация протокола BiSS вместо двух; пресеты
  разрядности (`BISS_LENZ_IRS_17BIT` / `18BIT`) вместо константы в `board.h`.
* **Чем платим.** Правка боевого пути чтения энкодера — того самого, на котором
  держатся closed-loop, стартовая диагностика и защита от блокировки вала. На
  ПК это не проверяется никак: модель прошивки имитирует строки протокола, а не
  SPI. Проверка — только на стенде с реальным энкодером LENZ IRS.

### Вариант 2. Оставить как отдельный переиспользуемый артефакт (текущее состояние)

Две библиотеки живут своей жизнью: общее ядро, два порта (STM32Cube HAL и
Arduino/STM32duino), свои `examples/`.

* **Что придётся сделать.** Ничего сверх уже сделанного: статус «прошивками не
  используется» записан в обоих README, ядро сверено побайтно.
* **Что это даёт.** Готовый переносимый драйвер для соседних проектов, в том
  числе под STM32duino, где HAL-версия не годится вовсе.
* **Чем платим.** Ядро продублировано в двух каталогах — при правке протокола
  BiSS его придётся синхронизировать руками (сейчас копии совпадают, и это
  свойство надо поддерживать). Код никем не собирается в CI кроме
  `examples/`, то есть гниёт молча.

### Вариант 3. Удалить

* **Что придётся сделать.** Удалить оба каталога и упоминания в корневом
  [README](../../../README.md).
* **Что это даёт.** В репозитории не остаётся кода, который никто не собирает
  и не проверяет.
* **Чем платим.** Потеря единственного в проекте порта BiSS под Arduino и
  рабочих примеров. История в git остаётся, но «лежит в истории» и «лежит в
  дереве» — разные вещи по доступности.

**Что нужно от владельца проекта:** ответ на один вопрос — планируется ли
второй проект на этих энкодерах. Если да — вариант 2 (и тогда стоит завести
сборку `examples/` в CI, иначе библиотека протухнет). Если нет — выбор между 1
и 3: свести, если нужна одна реализация протокола, удалить, если ценность
переносимости нулевая.
