# Test_TMC2209 — тестовая прошивка TMC2209 + STM32F103C8

Стенд для отладки драйвера шагового двигателя **TMC2209**: инициализация,
вращение мотора, настройка тока/микрошага и чтение диагностических регистров
через текстовый **UART CLI**.

## Аппаратная часть

### MCU

**STM32F103C8** (LQFP-48, «Blue Pill»). Тактирование от внутреннего
генератора **HSI 8 МГц → PLL → SYSCLK 48 МГц** (внешний кварц не требуется).

### Подключение TMC2209

```
STM32F103C8        TMC2209
──────────         ───────
PA2 (USART2_TX) ──┬── PDN_UART    (через R 1 кОм от PA2)
PA3 (USART2_RX) ──┘                (напрямую к PDN_UART)
PB8              ───── STEP
PB7              ───── DIR
PB6              ───── ENN         (LOW = вкл, HIGH = выкл)
```

CLI-терминал подключается к **USART1** через любой USB-UART переходник (3.3 В):

```
STM32F103C8        USB-UART (3.3 В)
──────────         ───────────────
PA9  (USART1_TX) ───── RX          (ответы прошивки в терминал)
PA10 (USART1_RX) ───── TX          (команды с ПК)
GND              ───── GND
```

### Схема подключения UART к TMC2209 (single-wire)

TMC2209 использует **однопроводной UART** на пине PDN_UART.
MCU подключается двумя линиями (TX + RX) к одному пину TMC2209:

```
         1 кОм
PA2 (TX) ──[===]──┬── PDN_UART (TMC2209)
                  │
PA3 (RX) ─────────┘
```

Резистор 1 кОм на TX предотвращает конфликт при одновременной передаче
(MCU TX + ответ TMC2209 на той же линии). RX подключён напрямую.

### Адресация TMC2209

Адрес задаётся пинами MS1/MS2 на TMC2209:

| MS1 | MS2 | Адрес |
|-----|-----|-------|
| GND | GND | 0     |
| VCC | GND | 1     |
| GND | VCC | 2     |
| VCC | VCC | 3     |

В прошивке: `TMC2209_UART_ADDR = 0` (MS1=GND, MS2=GND).

### Питание TMC2209

```
         TMC2209
         ┌──────────┐
VM ──────┤ VS       │   Питание мотора: 4.75–29 В
         │          │
VCC_IO ──┤ VCC_IO   │   Логика: 3.3 В (от STM32)
         │          │
GND ─────┤ GND      │
         │          │
    ┌────┤ OA1  OB1 ├────┐
    │    │          │    │   Обмотки шагового
  Motor  │ OA2  OB2 │  Motor  двигателя (A и B)
  Coil A └──────────┘  Coil B
```

**Обязательные конденсаторы:**
- **100–470 мкФ** (электролит, low ESR) между VS и GND — как можно ближе к TMC2209
- **100 нФ** керамика между VS и GND — рядом с микросхемой
- **100 нФ** керамика между VCC_IO и GND
- **2.2 мкФ** между 5VOUT и GND (выход внутреннего регулятора)

> ⚠️ Линию питания VS **всегда** подключайте через электролитический
> конденсатор — иначе выбросы напряжения могут повредить TMC2209.

### Токоизмерительные резисторы (Rsense)

Прошивка настроена на **Rsense = 0.11 Ом** (внешние резисторы).
Устанавливаются между выводами BRA/GND и BRB/GND.

Ток задаётся в `board.h`:
- `TMC2209_IRUN_MA = 800` — ток при движении (мА)
- `TMC2209_IHOLD_MA = 400` — ток удержания (мА)

### Сводная таблица пинов STM32F103C8

| Пин  | Функция                   | Назначение     | Примечание                          |
|------|---------------------------|----------------|-------------------------------------|
| PA9  | USART1_TX                 | CLI            | Ответы прошивки в терминал          |
| PA10 | USART1_RX                 | CLI            | Команды с ПК                        |
| PA2  | USART2_TX                 | TMC2209 UART   | Через 1 кОм к PDN_UART             |
| PA3  | USART2_RX                 | TMC2209 UART   | Напрямую к PDN_UART                 |
| PB6  | GPIO OUT                  | TMC2209 ENN    | LOW = драйвер вкл                  |
| PB7  | GPIO OUT                  | TMC2209 DIR    | Направление вращения                |
| PB8  | GPIO OUT / TIM4_CH3 (AF)  | TMC2209 STEP   | GPIO в UART-режиме, PWM в SD-режиме  |

### Тактирование

```
HSI 8 МГц → /2 → PLL ×12
  SYSCLK = 48 МГц
  AHB    = 48 МГц
  APB1   = 24 МГц  (таймеры APB1 = 48 МГц)
  APB2   = 48 МГц
```

## Прошивка

### Сборка

Требуется [PlatformIO](https://platformio.org/):

```
pio run
```

Код проекта собирается со строгими предупреждениями `-Wall -Wextra`
(`build_src_flags` в [platformio.ini](platformio.ini) — именно `build_src_flags`,
чтобы флаги не попали на исходники STM32Cube HAL). Общие библиотеки из
`Software/lib` включают те же флаги у себя в `library.json`. Сборка должна
проходить без единого предупреждения в нашем коде.

### Загрузка (WCH-Link / CMSIS-DAP + OpenOCD)

Программатор — WCH-Link (в режиме CMSIS-DAP, SWD). Конфиг адаптера —
`openocd/wch-link.cfg`. Загрузка:

```
pio run -t upload
```

Команда прошивки (уже прописана в `platformio.ini`):

```
openocd -f openocd/wch-link.cfg -f target/stm32f1x.cfg \
        -c "program .pio/build/stm32f103c8/firmware.bin 0x08000000 verify reset" \
        -c "shutdown"
```

### Режимы управления

**UART (по умолчанию)** — TMC2209 использует встроенный генератор шагов.
Скорость задаётся через регистр VACTUAL. Пины STEP/DIR игнорируются.
Знак значения определяет направление.

**STEP/DIR** — MCU генерирует импульсы на пине STEP через TIM4 (PWM).
Пин DIR задаёт направление. VACTUAL = 0, TMC2209 слушает внешние импульсы.

### Команды (CLI-терминал, 115200 8N1)

| Cmd     | Описание                                                          |
|---------|------------------------------------------------------------------|
| `h`     | Список команд (справка)                                          |
| `i`     | Инициализация / переинициализация TMC2209                        |
| `m<N>`  | Движение: UART — VACTUAL, STEP/DIR — шагов/сек (знак = направление) |
| `ms<N>` | Микрошаг (1, 2, 4, 8, 16, 32, 64, 128, 256)                      |
| `ir<N>` | Ток движения, мА                                                 |
| `ih<N>` | Ток удержания, мА (≤ тока движения)                              |
| `s`     | Стоп                                                             |
| `e`     | Включить драйвер (ENN=LOW)                                       |
| `d`     | Выключить драйвер (ENN=HIGH)                                     |
| `p`     | Режим STEP/DIR                                                   |
| `u`     | Режим UART                                                       |
| `st`    | Краткий статус (DRV_STATUS)                                      |
| `t`     | Полная телеметрия (GSTAT, IOIN, DRV_STATUS, MSCNT, … все регистры) |
| `v`     | Версия IC (ожидается 0x21)                                       |
| `a`     | Сканирование адресов 0..3 на шине                                |
| `r`     | Разовое чтение IOIN                                              |
| `diag`  | Конфигурация драйвера + проверка связи (чтение IOIN)             |
| `c`     | Периодический вывод CS_ACTUAL (тока), останов командой `s`       |

### Примеры

```
h              → список команд
v              → IC=0x21 OK
ir600          → irun=600 mA
ms32           → microsteps=32
m500           → UA=500     (UART: VACTUAL=500)
s              → stop
p              → mode:SD    (переключить в STEP/DIR)
m1000          → SD=1000    (1000 шагов/сек вперёд)
m-500          → SD=-500    (500 шагов/сек назад)
s              → stop
u              → mode:UA    (вернуться в UART)
st             → DRV=0x... [UA]
```

### Структура проекта

```
Test_TMC2209/
├── include/
│   ├── board.h            — конфигурация пинов, токов, тактирования, таймера
│   └── stm32f1xx_hal_conf.h — свой набор модулей STM32Cube HAL (см. ниже)
├── src/
│   └── main.c             — main loop, UART CLI, режимы UART / STEP-DIR
├── openocd/
│   └── wch-link.cfg       — конфиг адаптера WCH-Link (CMSIS-DAP/SWD)
├── docs/
│   ├── TMC2209_API.md     — описание API библиотеки tmc2209
│   └── examples/          — примеры использования библиотеки TMC2209
├── tools/
│   ├── serial_monitor.py  — монитор COM-порта: чтение и проверка телеметрии (регистры GSTAT/IOIN/DRV_STATUS и т.д.)
│   ├── test_commands.py   — автотест всех CLI-команд с логом TX/RX (лог пишется в logs/)
│   └── requirements.txt   — зависимости для скриптов (pyserial)
├── platformio.ini
└── README.md
```

Библиотека драйвера вынесена в общий каталог
[`../lib/tmc2209`](../lib/tmc2209/README.md) — одна копия на этот стенд и на
основную прошивку `FW_SonarMotorDriver`, чтобы правки в протоколе TMC2209 не
приходилось переносить руками:

```
Software/lib/tmc2209/
├── library.json
├── include/tmc2209/       — публичный API, карта регистров, типы, контракт порта
└── src/                   — ядро протокола + порт STM32 HAL + фасад мотора
```

Подключается строкой `lib_deps = symlink://../lib/tmc2209` в `platformio.ini`.
Библиотека берёт `board.h` из `include/` стенда — оттуда приходят
`TMC2209_UART*`, токи, микрошаг и выводы STEP/DIR/ENN. Фасад `tmc2209_motor_*`
стенду не нужен (импульсы STEP формирует сам `main.c`, VACTUAL задаётся
командами CLI), и он **не компилируется вовсе**: тело `tmc2209_motor.c` закрыто
`#ifdef TMC2209_USE_MOTOR_FACADE`, а этого флага в `platformio.ini` стенда нет —
он есть только у основной прошивки. Поэтому и параметров фасада (режим движения,
SENDDELAY, TPOWERDOWN, SPREADCYCLE, инверсия направления) в `board.h` стенда
больше нет.

### Своя конфигурация HAL

`include/stm32f1xx_hal_conf.h` вместе с
`board_build.stm32cube.custom_config_header = yes` в `platformio.ini` делает
сборку стенда независимой от соседних проектов. Раньше своего заголовка у
стенда не было, и он брал общий `stm32f1xx_hal_conf.h` из каталога пакета
`framework-stm32cubef1`. Пакет один на все прошивки: сборка проекта со своим
заголовком этот общий файл оттуда удаляет, а сборка без него — создаёт заново
из шаблона ST. Поэтому стенд собирался или не собирался в зависимости от того,
какую прошивку собрали перед ним («Implicit dependency stm32f1xx_hal_conf.h not
found»). Содержимое повторяет шаблон ST, из которого раньше и создавался общий
файл, но включены только нужные стенду модули HAL, поэтому прошивка осталась
байт-в-байт прежней.

> **Изменённое поведение, на железе не проверялось.** Стенд перевели на общую
> библиотеку в ходе правок по документации и сборке, платы при этом не было —
> прогонов `tools/test_commands.py` и `tools/serial_monitor.py` после перехода
> не делали. Что именно изменилось в самой прошивке стенда:
>
> 1. **`HAL_UART_MspInit` для USART2 делегирован библиотеке.** Раньше стенд
>    настраивал PA2/PA3 сам, теперь зовёт `tmc2209_port_stm32_hal_uart_msp_init()`
>    (`src/main.c`, ветка `h->Instance == TMC2209_UART`). Выводы те же
>    `TMC2209_UART_*` из `board.h`, но код инициализации — другой.
> 2. **DWT включается локально.** Из библиотеки убрана
>    `tmc2209_port_stm32_dwt_init()`; счётчик тактов (на нём держатся
>    микросекундные паузы протокола PDN_UART) теперь поднимает `dwt_init()` в
>    `src/main.c` до первого обращения к драйверу. Если бы порядок нарушился,
>    задержки схлопнулись бы в ноль — а это ломает тайминги однопроводного UART.
> 3. **Ядро библиотеки стало общим с основной прошивкой** — вместе с
>    исправлением UB в разборе OTP и правками PWMCONF, которых в прежней копии
>    стенда не было.
>
> Проверено только сборкой (`pio run`, без предупреждений) и чтением кода.
> Первый прогон на стенде считать отладочным: начинать с команд `i` (init),
> `st` (статус) и `t` (все регистры) — если DWT не поднялся, микросекундные
> паузы схлопываются и драйвер по PDN_UART не ответит вовсе.

**Автотест и монитор (`tools/`):** требуют `pip install -r tools/requirements.txt`.

```bash
python tools/test_commands.py COM19       # автотест всех команд, лог в logs/
python tools/test_commands.py COM19 --no-test   # только лог TX/RX, без проверок
python tools/serial_monitor.py COM19      # монитор телеметрии (t / c) с проверкой значений
```

### Параметры в board.h

| Параметр                | Значение | Описание                          |
|-------------------------|----------|-----------------------------------|
| `SYSCLK_HZ`             | 48000000 | Тактовая частота, Гц (HSI+PLL)   |
| `CLI_UART_BAUDRATE`     | 115200   | Скорость CLI (USART1)             |
| `TMC2209_UART_BAUDRATE` | 115200   | Скорость UART к TMC2209 (USART2)  |
| `TMC2209_UART_ADDR`     | 0        | Адрес (MS1=GND, MS2=GND)         |
| `TMC2209_RSENSE_OHM`    | 0.11     | Rsense, Ом                        |
| `TMC2209_IRUN_MA`       | 800      | Ток движения, мА                  |
| `TMC2209_IHOLD_MA`      | 400      | Ток удержания, мА                 |
| `TMC2209_MICROSTEPS`    | 16       | Микрошаг (1–256, степень двойки)  |
| `TMC2209_REPLY_DELAY_US`| 500      | Пауза TX→RX перед ответом драйвера, мкс |
| `TMC2209_HALF_DUPLEX`   | 0        | PA2/PA3 разведены раздельно — full-duplex |

Макроса `MOTOR_DRIVER_MODE` в `board.h` стенда нет: он относится к фасаду
`tmc2209_motor_*`, который здесь не компилируется (см. выше).
